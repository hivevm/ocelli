# Every place of the locked git2's source outside its tests that panics by itself, audited
# (git2_unwraps.rs). A line reads `file function | verdict | statement`; the verdict is one of
#   internal: why          the site holds whatever string a caller, a repository, or a remote
#                          gives, as git2 and the libgit2 of the libgit2-sys named below behave
#   disallowed: path, …    a string reaches the site through these methods; clippy.toml
#                          disallows each, and Ocelli calls one, if at all, in a guarded wrapper
#                          of guard.rs or where its `expect` says why the string is safe
#   unreachable: why       nothing Ocelli does reaches the site
# On Windows `util.rs bytes2path` unwraps a path as UTF-8. Repository::path, commondir, and
# workdir, Index::path, and Repository::discover hand it only a path libgit2 resolved or opened
# through the file system, which on Windows it converts to UTF-16 and refuses where it is not
# UTF-8; Config::find_global and its kin a path of the developer's environment. Submodule::path
# and Worktree::path are called on Windows only where Ocelli read the files libgit2 takes the
# path from as UTF-8; libgit2 reads them on its own, so one another program rewrites between
# the two reads still reaches the unwrap there.
