# Cases of scripts/check-traceability.sh for identifiers, read by
# scripts/test-check-traceability.sh.
#
# One case per line, four fields separated by ' | ':
#
#   <pass or fail> | <what the output holds, or -> | <name> | <tree>
#
# A run exits 0 for pass and 1 for fail. The second field is '<key>', then ' @ <subject>' for each
# datum the line names, such as an identifier. A line of the output ends in '[<key>]', the rule and
# a reason word, and holds each subject, in that order and with no ASCII letter, digit, hyphen,
# or underscore beside it; the rest of its wording is free.
#
# A line that starts with '#' is a comment, not a case. The subjects are looked for in the part of
# the line before its key, so that none holds by the key alone. A field may start with '!': it then
# holds where no line that ends in '[<key>]' holds the subjects in their order, so a field
# '!<key> @ <a> @ <b>' is not broken by a line that names <b> before <a>.
#
# The tree is a list of steps separated by '; ', applied in order to a git repository with no
# commit, an empty docs/adr/ and an empty tests/, and nothing else. Every file is staged before the
# check runs.
#
#   spec <text>                 docs/SPECIFICATION.md, with the text as its one goal:
#                                 # Specification
#
#                                 ## Goals / Success Criteria
#
#                                 - <text>
#
#                                 ## Quality Goals
#
#                                 - **Q-1** — fast enough.
#
#                                 ## Non-Goals
#
#                                 - none
#   adr <id> <status>           docs/adr/<id>.md, with no exemption:
#                                 # <id>: decision
#
#                                 - **Status:** <status>
#
#                                 ## Enforcement
#
#                                 Review only.
#   mark <file> <ids>           the file, holding the one line 'Verifies: <ids>'
#   file <file>                 the file, holding the one line 'text' and no marker
#
# A status reads '🟢 accepted', '🟡 proposed', or, for superseded:<id>, '⚪ superseded by <id>'. An id
# is written as in scripts/fixtures/check-docs-record.txt, and so is the notation of that file's
# header: a colon after two to five capital letters, not preceded by a letter, a digit, or '_', and
# before a letter or a digit, reads as a hyphen.
