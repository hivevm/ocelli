# Cases of scripts/check-docs.sh, read by scripts/test-check-docs.sh: every case of its self-test
# but the few it keeps inline and says why.
#
# One case per line, five fields separated by ' | ':
#
#   <check> | <pass or fail> | <what the output holds, or -> | <name> | <tree>
#
# The check is the number of the check in the header of check-docs.sh, or 'all' for a case of every
# check. The tree is the rest of the line, so it may hold ' | ' itself.
#
# A run exits 0 for pass and 1 for fail. The third field is '<key>', then ' @ <subject>' for each
# datum the line names, such as a file or an identifier. A line of the output ends in '[<key>]', the
# rule and a reason word, and holds each subject, in that order and with no ASCII letter, digit,
# hyphen, or underscore beside it; the rest of its wording is free. '<deleted>' stands for the
# short hash of the commit of the last delete.
#
# A line that starts with '#' is a comment, not a case. The subjects are looked for in the part of
# the line before its key, so that none holds by the key alone. A field may start with '!': it then
# holds where no line that ends in '[<key>]' holds the subjects in their order, so a field
# '!<key> @ <a> @ <b>' is not broken by a line that names <b> before <a>.
#
# The tree is a list of steps separated by '; ', or '-' for none, applied in order to a git
# repository, with no commit and without TEMPLATE-SETUP.md, that passes every check, its setup
# done. Every file is staged before the check runs. Its files, where 'exactly' gives the whole
# content, each '\n' a line break:
#
#   AGENTS.md                     exactly '# Agent Guide\n\n## 1. Principles\n\nBe simple.\n\n
#                                 ## 2. Rules\n\nFollow them.\n'
#   README.md                     exactly '# Fixture\n\n## Template\n\n- **Template release:**
#                                 unreleased\n'
#   CONTRIBUTING.md               '# Contributing'; '## Project Layout' with a fenced block of one
#                                 line per path, '<path>  # <what it is>', in this order: README.md,
#                                 CONTRIBUTING.md, AGENTS.md, docs/adr/, scripts/, .github/,
#                                 .agents/skills/, .claude/skills/; '## Repository settings' with
#                                 the lines '<!-- required-checks begin -->', '`docs`', and
#                                 '<!-- required-checks end -->'
#   .github/workflows/checks.yml  exactly 'jobs:\n  docs:\n    steps:\n      - run: bash
#                                 scripts/check-docs.sh\n'
#   scripts/check-all.sh          the line 'run "Documentation consistency" scripts/check-docs.sh'
#   docs/adr/template.md          '# <CAT>-<slug>: title', '- **Status:** 🟡 proposed', and
#                                 '*Complete the header and delete this paragraph.*'
#   docs/adr/OPS:fixture-<role>.md  for the roles harness and toolchain, the two required:
#                                 '# OPS:fixture-<role>: decision', '- **Status:** 🟢 accepted',
#                                 '- **Role:** <role>', '- **Applies to:** everything'
#   docs/adr/README.md            '# ADRs'; '### Categories' with '- **NUC** — the template.';
#                                 '### Binding' with a table of the two role ADRs; and
#                                 '### Superseded and rejected' with an empty table. Each table has
#                                 the header '| ADR | Title | Applies to | Status |' and its
#                                 delimiter row '|-----|-------|------------|--------|', and a row reads
#                                 '| [<id>](<id>.md) | Decision | everything | <status> |'
#   .agents/skills/review/SKILL.md  exactly '---\nname: review\ndescription: Review a change.\n
#                                 ---\n\n# Review\n'
#   .claude/skills/review         a symlink to ../../.agents/skills/review
#
# The steps:
#
#   adr <id> <status>           the ADR file and its index row, in the table its status belongs to
#   file <id> <status>          the ADR file alone, exactly: '# <id>: decision\n\n- **Status:**
#                               <status>\n- **Applies to:** everything\n\n## Decision\n\nWe will.\n'
#   row <table> <id> <status>   an index row alone, in 'binding' or 'archive'
#   status <id> <status>        the status line of the file alone
#   field <id> <name> <text>    a header field '- **<name>:** <text>' before Applies to, such as Role
#   supersedes <id> <ids>       a Supersedes field before Applies to, linking each id of the
#                               comma-separated list as [<id>](<id>.md); an id after '+' stands on
#                               a continuation line
#   heading <id> <text>         the first line of the file replaced by the text
#   text <file> <text>          the text appended to the file as one more line, each '\n' in it a
#                               line break; the file and its directories are made when absent
#   write <file> <text>         the file written with exactly the text, each '\n' in it a line break
#   edit <file> <old> => <new>  the first line of the file that starts with the old text replaced
#                               by the new, the first ' => ' splitting the two; with nothing
#                               after '=>', that line removed. No line that starts with the old
#                               text stops the run, an error of the table
#   rm <path>                   the file, directory, or symlink removed
#   link <path> <target>        a symlink at the path to the target, its directories made
#   layout <path>               the line '<path>  # added' in the Project Layout block, right
#                               after the line of AGENTS.md
#   category <key>              '- **<key>** — a category of the project.' in the category list
#   blobs                       the blob list docs/adr/NUC.blobs written from the files: a line
#                               '<git blob identifier> <file>' for each NUC- file and AGENTS.md
#   release <text>              the README's Template release line reading '- **Template
#                               release:** ' and the text
#   setup                       TEMPLATE-SETUP.md present, as before the setup is done, and named
#                               in the Project Layout
#   commit                      every file committed
#   delete <id>                 the file and its row deleted and committed
#   branch <name>               a new branch, checked out
#   back                        the branch checked out before
#   merge <name>                the branch merged by a merge commit
#   skill <text>                the SKILL.md of the fixture's skill 'review' replaced by the text,
#                               each '\n' in it a line break
#
# The text of a step is all of it after the file and the one space that follows, leading spaces
# kept. In the text of text and write, '<prose N>' stands for N characters of prose: 'word '
# repeated, cut after the Nth character.
#
# An id is '<CAT>:<slug>', the file <CAT>-<slug>.md. A status is accepted (🟢 accepted), proposed
# (🟡 proposed), rejected (🔴 rejected), or superseded:<id> (⚪ superseded by <id>). Everywhere in a
# line, a colon after two to five capital letters, not preceded by a letter, a digit, or '_', and
# before a letter or a digit reads as a hyphen: written so, an identifier cites no ADR of this
# repository, and the map script of the normalize skill leaves it as it is. A row may name an ADR
# of this repository, such as one a message of the check cites, by its identifier with a hyphen;
# that cites the ADR, and the map script moves it with the rest of the tree.
